1. КОНЦЕПЦИЯ И БИЗНЕС-НАЗНАЧЕНИЕ ПРОЕКТА
--------------------------------------------------------------------------------

Synapse AI — это интеллектуальное рабочее пространство разработчика нового поколения
(Developer Workspace), вдохновленное Cursor, Windsurf и GitHub Copilot Workspace,
но с глубокой архитектурной визуализацией кода через абстрактные синтаксические деревья (AST).

Бизнес-задачи и ценность для команд разработки:
1. Сокращение времени онбординга и код-ревью сложных модулей:
   Разработчик видит не просто плоский текст файлов, а живую топологию связей функций,
   интерфейсов и классов через интерактивный нейро-граф связей (AST Neural Canvas).

2. Устранение критических уязвимостей и утечек памяти (Memory Leaks):
   Встроенные эвристики и AI-инструменты мгновенно находят неэффективный кэш без TTL,
   гонки потоков (Race Conditions) и небезопасную работу с криптографией,
   предлагая готовый визуальный Diff с кнопками "Accept Refactor" и "Reject".

3. Непрерывный цикл валидации (Instant Test & Coverage Loop):
   Прямо в интерфейсе запускается эмуляция тестового фреймворка Jest,
   проверяющая граничные условия, устойчивость к OOM и криптографическую валидность токенов.

4. Прозрачность рассуждений ИИ (Explainable AI / Chain-of-Thought):
   Поддержка reasoning-моделей (DeepSeek R1, Claude 3.7) с отдельным сворачиваемым
   блоком мышления позволяет разработчику видеть ход логических рассуждений нейросети
   до того, как принять предложенный код в продакшн.

2. ТЕХНОЛОГИЧЕСКИЙ СТЕК И АРХИТЕКТУРА
--------------------------------------------------------------------------------

2.1. Frontend Architecture:
• Полноэкранный CSS Grid Лейаут (Full-Bleed 3-Pane Workspace):
  - Контейнер .synapse-container занимает 100vw и ровно 100vh без полос прокрутки страницы;
  - Сетка .workspace-grid: 260px (дерево файлов) | minmax(0, 1fr) (редактор и AST) | 420px (AI Copilot);
  - Центральный редактор тянется на всю доступную ширину ультрашироких и стандартных мониторов;
  - Flexbox-верстка с overflow: hidden предотвращает сжатие панелей при переполнении.

• Двухуровневый Canvas 2D движок:
  1. Фоновый ambient-канвас (synapse-ambient-canvas):
     32 частицы с броуновским движением, линиями связей на расстоянии < 110px
     и мягким отталкиванием/притяжением к курсору мыши.
  2. AST Neural Network Canvas (ast-canvas):
     Рендерит семантические узлы текущего активного файла (функции, интерфейсы,
     криптографические модули), соединяя их кривыми Безье третьего порядка.
     По синапсам непрерывно циркулируют светящиеся кванты данных с динамическим затуханием.

• Механизм синтаксической подсветки и Diff Engine:
  - Собственный легковесный токенизатор кода (keywords, strings, functions, types, numbers);
  - Двухколоночный / инлайн Diff Viewer с цветовой маркировкой удалений (del, красный фон)
    и добавлений (add, изумрудный фон);
  - Функция мгновенного применения правок (Accept) с перезаписью состояния файла в памяти
    и триггером взрыва конфетти (canvas-confetti).

2.2. Архитектура в Production (Enterprise Scale):
• Парсинг AST: Babel Parser / SWC в фоновом Web Worker (WebAssembly) для парсинга файлов > 50 000 строк без фризов UI.
• LSP (Language Server Protocol): WebAssembly-клиент Pyright/TypeScript для автокомплита.
• Streaming LLM: Server-Sent Events (SSE) с протоколом chunk-декодирования и токенизацией на лету.
• State Management: Zustand + Yjs (CRDT) для совместного редактирования кода в реальном времени.

3. КЛЮЧЕВОЙ ФУНКЦИОНАЛ И ИНТЕРАКТИВНЫЕ ФИЧИ
--------------------------------------------------------------------------------

1. Интерактивное дерево проекта и переключение файлов:
   - 4 предзагруженных продакшн-файла:
     * jwt.ts (TypeScript реализация JWT авторизации с утечкой памяти в Map);
     * payment.ts (Idempotent Stripe Webhook процессинг транзакций);
     * synapse.ts (Ядро AI Worker Pipeline с кэшем эмбеддингов);
     * auth.test.ts (Jest юнит-тесты на JWT и валидацию сессий).
   - При переключении файла мгновенно обновляются:
     * Вкладки открытых файлов с крестиком закрытия и статусом сохранности;
     * Счетчик строк и размер файла;
     * Дерево символов AST (функции, классы, интерфейсы) с цветными бейджами типов;
     * Топология графа узлов в AST Neural Canvas;
     * Процент тестового покрытия (Code Coverage).

2. Двухрежимный редактор (Editor Mode & Diff Viewer):
   - Режим "Original": подсветка чистого кода файла с нумерацией строк.
   - Режим "Diff Review": детальный список изменений кода с удаленными (розовые/красные)
     и добавленными (зеленые) строками, комментариями оптимизации и баунд-лимитами.
   - Кнопка "Accept": заменяет исходный код на отрефакторенный, показывает нотификацию
     "Code merged successfully!" и запускает салют конфетти.
   - Кнопка "Reject": отменяет изменения и возвращает чистый исходный код.

3. Интерактивный AST Neural Network Canvas:
   - Векторные узлы с иконками типов (fn, class, type, crypto);
   - Интерактивное перетаскивание узлов курсором мыши (Drag & Drop) в реальном времени;
   - Пульсирующие сигналы, путешествующие по синаптическим связям;
   - Кнопка "Analyze AST": запускает симуляцию оптимизации синтаксического дерева
     с перерасчетом метрик связности и сложности.

4. Выдвижной терминал тестирования (Jest Test Runner Drawer):
   - Нижняя панель с переключением между вкладками "Test Suites (Jest)" и "Terminal Output";
   - Кнопка "Run Tests": запускает живую анимацию прогона 4 наборов тестов с микро-задержками,
     показывает статус PASS, время выполнения (2.14s) и зеленые индикаторы прохождения.
   - Детальный отчет покрытия: Statements 96.4%, Branches 92.1%, Functions 100%, Lines 95.8%.

5. Интеллектуальный Copilot с переключением моделей и скрытым мышлением:
   - Селектор модели в шапке панели:
     * Claude 3.7 Sonnet (Hybrid Reasoning);
     * DeepSeek R1 (Deep CoT / Open Weights);
     * GPT-4.5 Turbo (High-Recall Architecture);
     * Gemini 2.5 Pro (Multimodal 2M Context).
   - Блок скрытых рассуждений (<thought> Reasoning Stream):
     * Показывает ход внутренних логических шагов модели (анализ утечки памяти, выбор LRU-политики, проверка совместимости с Jose v5);
     * Сворачивается и разворачивается по клику с плавной CSS-анимацией.
   - Быстрые промпты (Quick Prompts):
     * "Refactor Memory Leak" — запускает рефакторинг кэша с генерацией диффа;
     * "Explain Security Flow" — генерирует разбор цепочки безопасности с диаграммой;
     * "Generate Unit Tests" — пишет полный набор граничных тестов для Jest.
   - Живое поле ввода сообщений с поддержкой Enter и генерацией контекстных ответов.

6. Действия тулбара редактора:
   - Кнопка "Format": форматирует код с анимацией и всплывающим тостом "Prettier formatted 0 errors".
   - Кнопка "Copy": копирует активный код в буфер обмена с подтверждением в тосте.
   - Кнопка "Analyze AST": фокусирует внимание на синтаксическом графе.

Сценарий показа проекта работодателю (5-7 минут):

ШАГ 1: Полноэкранный обзор и концепция IDE (1 минута)
• Откройте страницу http://localhost:3000/demos/synapse/index.html в полноэкранном режиме (F11).
• Обратите внимание на компоновку:
  "Перед вами Synapse AI — среда разработки нового типа, объединяющая текстовый код,
   визуальный граф синтаксического дерева (AST) и контекстный ИИ-копилот с прозрачным ходом рассуждений.
   Обратите внимание на сетку: вся рабочая область адаптируется без малейшего горизонтального
   скролла, центральный редактор занимает всё доступное пространство, а на фоне работает
   фоновый Canvas со связанными нейро-частицами."

ШАГ 2: Переключение файлов и AST Symbol Explorer (1 минута)
• В левой колонке покликайте по файлам: jwt.ts -> payment.ts -> synapse.ts.
• Покажите, как синхронно меняются:
  1. Вкладки в заголовке редактора;
  2. Блок "AST Symbol Hierarchy" в левой панели (функции, интерфейсы, классы с подсветкой типов);
  3. Граф синтаксического дерева справа от кода;
  4. Метрики покрытия тестами в нижней строке статуса.

ШАГ 3: Решение проблемы Memory Leak через AI Copilot и Diff Review (2 минуты)
• Вернитесь на файл jwt.ts.
• В правой панели Copilot нажмите на быстрый чип: "[ ⚡ Refactor Memory Leak ]".
• Обратите внимание интервьюера:
  "В исходном файле класс TokenCache использует бесконечно растущий Map<string, TokenPayload>
   без времени жизни записей (TTL) и без ограничения по размеру. При миллионе запросов
   в Node.js это неизбежно вызовет Out-Of-Memory (OOM crash)."
• Покажите сгенерированный ответ ассистента:
  1. Раскройте блок [ v Thinking Process (6 steps) ] и покажите логику рассуждений модели;
  2. Нажмите кнопку [ Compare Diff ] в сообщении ИИ.
• Интерфейс автоматически переключится в режим Diff Viewer:
  "Здесь виден точный расчет изменений: красные строки старого Map удалены,
   добавлен LRU-эвикшн при превышении 5000 записей и автоматический TTL 3600 секунд."
• Нажмите изумрудную кнопку [ ✓ Accept Refactor ]: сработает салют конфетти,
  код обновится в исходном файле, а статус файла изменится на Refactored.

ШАГ 4: Интерактивный AST Neural Canvas (1 минута)
• Переместите курсор на правый холст с синтаксическим деревом.
• Зажмите левой кнопкой мыши любой узел (например, signAccessToken или TokenCache)
  и подвигайте его по канвасу. Покажите, как плавно изгибаются синусоидальные кривые Безье
  и как по ним продолжают течь световые пакеты данных.
• Нажмите кнопку [ ⚡ Analyze AST ] в тулбаре редактора. Покажите тост и анимацию связей.

ШАГ 5: Запуск тестового раннера Jest (1 минута)
• Внизу экрана кликните кнопку [ ▶ Run Tests ].
• Продемонстрируйте прогон тестов:
  Счетчики плавно переключаются с Running на 4 Passed, время выполнения 2.14s,
  индикаторы покрытия заполняются на 96.4%.
• Откройте вкладку "Terminal Output" и покажите чистый лог сборки и линтинга.

ШАГ 6: Переключение моделей и контекстный диалог (1 минута)
• В правом верхнем углу панели Copilot переключите модель с Claude 3.7 на DeepSeek R1 или GPT-4.5.
• Введите произвольный вопрос в поле ввода (или нажмите чип [ 🛡️ Explain Security Flow ]).
• Покажите моментальный генеративный стрим ответа с форматированными блоками кода и бейджами.

5. ВОПРОСЫ И ОТВЕТЫ ДЛЯ ТЕХНИЧЕСКОГО ИНТЕРВЬЮ (FAQS)
--------------------------------------------------------------------------------

В: "Как в реальном проекте строится граф AST без замедления UI на больших файлах?"
О: "В продакшене парсинг AST делегируется в выделенный Web Worker с использованием
    скомпилированного в WebAssembly парсера (например, @swc/wasm или Tree-sitter).
    Главный поток UI никогда не блокируется: Worker парсит AST, сериализует граф
    топологии в бинарный буфер (ArrayBuffer / Transferable Objects) и отправляет
    в UI-поток только компактный список нод и ребер для отрисовки на Canvas 2D / WebGL."

В: "Почему для графа был выбран нативный Canvas 2D, а не DOM / SVG или готовая библиотека?"
О: "Canvas 2D обеспечивает стабильные 60 FPS при отрисовке десятков узлов, анимированных
    кривых Безье и пульсирующих световых фотонов данных. SVG при аналогичной динамике
    создает сотни DOM-нод, вызывая постоянные пересчеты геометрии (Reflow/Repaint).
    Прямой рендеринг на Canvas с поддержкой Retina devicePixelRatio гарантирует идеальную
    четкость шрифтов и минимальное потребление GPU памяти."

В: "Как реализован Diff Engine и слияние изменений?"
О: "Diff Engine рассчитывает построчную разницу по алгоритму Майерса (Myers Diff Algorithm).
    Каждая строка классифицируется по статусам: same, add, del.
    При нажатии Accept Refactor массив строк фильтруется от элементов del,
    новые строки add бесшовно встраиваются в результирующий буфер, после чего
    виртуальный документ обновляет внутреннее состояние без перезагрузки страницы."

В: "Каким образом отображаются рассуждения reasoning-моделей (Chain-of-Thought)?"
О: "При получении Server-Sent Events (SSE) ответа от API (DeepSeek R1 или Claude 3.7 Thinking)
    токены рассуждений заворачиваются в отдельный канал или тег <thought>...</thought>.
    Клиентский компонент распарсивает этот тег в изолированный сворачиваемый аккордеон,
    чтобы длинные выкладки математики или архитектурного анализа не загромождали финальный код,
    но всегда были доступны по клику для верификации инженерных решений."
